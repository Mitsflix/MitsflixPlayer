# Running Mitsflix Player (maintainer notes)

## How updates work
- **OwnTV updates (automatic):** every morning the *Follow OwnTV releases* workflow checks OwnTV.
  When OwnTV publishes a new version (say v5.3.0), it is merged in, the Mitsflix wording and README
  feature list are refreshed, and Mitsflix Player v5.3.0 is built, signed and released. Installed
  copies offer the update.
- **If a merge needs a hand:** nothing is published and an issue is opened on this repository
  saying which files. Ask Claude to fix it.
- **Run it now:** Actions → Follow OwnTV releases → Run workflow.

## Publishing a Mitsflix-only update
Add a new section at the top of `CHANGELOG-MITSFLIX.md` with the next number (for example
`## v5.2.1.2`) and a few bullet points, and commit it to main. The *Publish Mitsflix updates*
workflow tags it, and the build signs and publishes it. The number must be higher than the current
release. Mitsflix numbers have a 4th part on top of the OwnTV version (v5.2.1.1, v5.2.1.2, …).

## TMDB (movie info, posters, Now Trending)
Add a free TMDB API key as the repository secret `TMDB_API_KEY`. Every build after that uses it.

## Where the Mitsflix changes live
- Branding constants: `app/build.gradle.kts` (MITSFLIX_* fields) and `app/src/main/java/tv/own/owntv/MitsflixBrand.kt`
- Texts: `app/src/main/res/values/mitsflix.xml`; renamed OwnTV texts are generated by `tools/mitsflix/rebrand_strings.py`
- Artwork: `extras/mitsflix-logos/` (sources) and `app/src/main/res/*/mitsflix_*`
- README: edit `tools/mitsflix/README.template.md`, then run `tools/mitsflix/build_readme.py`

## Signing
Releases are signed with the key in `signing/mitsflix-release.keystore.enc`, opened by the
`KEYSTORE_PASSWORD` repository secret. Keep your own copy of the key and password safe.
